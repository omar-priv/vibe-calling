# Visual Reference Research

## Workflow
1. Confirm the product, audience, main task, platform, and constraints before choosing a visual direction.
2. Inspect the actual reference URL when one is supplied. Distinguish observable details from assumptions; never claim to have viewed an inaccessible page.
3. Record concrete patterns: navigation, content hierarchy, spacing, type scale, color roles, component states, responsive behavior, and interaction flow.
4. Compare at least two relevant patterns when the choice materially affects usability. Prefer primary product pages and current documentation over vague inspiration galleries.
5. Create a compact reference board in text: pattern, evidence, why it works, what should or should not transfer.
6. Translate references into the existing project's design tokens and components. Do not copy another product's logo, proprietary assets, or exact distinctive composition.
7. Validate the design against the user's actual workflows, not screenshots alone.

## Output
- Evidence-based observations with links or file locations.
- Proposed design direction and rationale.
- Component inventory and interaction states.
- Risks, responsive considerations, and verification steps.

## Guardrails
- Never invent measurements, accessibility compliance, or test results.
- Keep branding original and respect licenses.
- Do not replace a working interface wholesale when targeted improvements are safer.
