# Vibe Calling — Hosted Edition

This is a separate deployment edition. The Windows/local edition remains unchanged.

## What this edition does

- Serves the existing Vibe Calling UI and API from one origin. The frontend's relative `/api/...` requests automatically reach this same hosted backend; no local URL or manual API-base setting is needed.
- Adds a private single-owner password gate. API routes, project files, previews, skills and downloads require a signed HttpOnly session cookie.
- Uses same-origin checks for browser POST requests, a login attempt throttle, secure cookie attributes, and standard browser security headers.
- Stores projects, uploads and custom skills under `VIBE_DATA_DIR` so they survive application restarts and redeploys when the host mounts persistent storage.
- Keeps provider API keys and MCP tokens in the user's browser storage, as the existing application does. Use a private browser profile and do not use shared school computers without signing out.

## Deploy on Render (no Docker)

1. Push/merge this branch to GitHub.
2. In Render, choose **New → Blueprint** and select this repository and branch `hosting/second-edition`.
3. Render reads `render.yaml`. The blueprint uses a Starter web service and a 1 GB persistent disk. Persistent disks are not available on Render's free web-service plan; this hosted app must not be deployed as a free ephemeral service if projects and uploaded files need to persist.
4. Set `VIBE_ACCESS_PASSWORD` to a unique password of at least 14 characters when Render prompts you. Do not reuse a school, email, or GitHub password.
5. `VIBE_SESSION_SECRET` is generated by Render. Keep it private.
6. Deploy. Wait for the service health check to pass, then open the generated HTTPS `.onrender.com` URL and sign in.
7. Add provider API keys from the Providers screen. The app uses the current page's origin for its backend automatically.

## Important limitations

- This is a private, single-owner hosted workspace, not a multi-user SaaS. Do not share the access password.
- The AI provider, GitHub MCP and remote MCP credentials are stored in browser local storage by the current UI. They are not encrypted by the app. Avoid shared/public browser profiles and sign out after use.
- Render persistent disks are attached to one service instance; do not scale this service horizontally.
- Static HTML project previews are served through the hosted app. Remote Vite/Next.js development-server preview and hot-module-reload are not included in this first hosted edition; use static output for previews. Build commands may also hit the memory limit of the smallest instance.
- The current project command allowlist executes on the hosted server. Keep this service private, use narrow provider/MCP permissions, and never expose it without the password gate.
- Render free instances sleep and have ephemeral filesystems; they are unsuitable for persistent agent projects. The included blueprint deliberately selects a paid Starter instance and persistent disk.
- A successful deployment/health check does not prove that every provider, model, MCP server, or project build command works. Test those integrations after deployment.

## Local hosted-mode smoke test

Set these environment variables before running:

- `VIBE_ACCESS_PASSWORD`: at least 14 characters
- `VIBE_SESSION_SECRET`: at least 32 random characters
- `VIBE_DATA_DIR`: writable directory, for example `./hosted-data`
- `PORT`: optional, defaults to 10000

Then run `python hosted_server.py`. Set `VIBE_COOKIE_SECURE=0` only for local HTTP smoke tests; leave it unset (secure cookies enabled) on Render. Visit `/__logout` to clear the hosted session. The original `start.bat` and `server.py` remain the local edition.
